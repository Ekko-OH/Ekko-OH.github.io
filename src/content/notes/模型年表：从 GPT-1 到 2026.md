> 按发布时间排的架构对照表。每一行是一个模型，每一列是它的一个部件选择。

> 收录规则：从 GPT-1（2018-06）起，按**版本**收录——同一条模型线的每个对外发布版本各占一行（GPT-5 / 5.1 / 5.2、DeepSeek-V3 / V3.1 / V3.2-Exp、Claude Opus 4.5 / 4.6 / 4.7 都分开列），`版本` 列写它的变体名（mini / Pro / Flash / 0324）。只收文本与多模态大模型，图像、视频、语音、TTS、嵌入、机器人类模型不收。表格按季度补充。

## 一、先看口径

19 列里有一半是缩写，先把口径定死，后面才不会各说各话。

| 列 | 取值 | 含义 |
| --- | --- | --- |
| 版本 | `mini` / `Pro` / `Flash` / `0324` | 同一条模型线的变体名。写 `—` 表示该版本没有额外代号；同一行的层数/参数只适用于该版本 |
| 类型 | `Dense` / `MoE` / `未公开` | 稠密模型，还是稀疏专家；`MoE·256+1 专家` 表示 256 个路由专家 + 1 个共享专家；`·推理` 表示以 RL 训练思维链为主，`·多模态` 表示原生多模态；`Dense/MoE` 表示同一代里两种规格都有 |
| 开闭源 | `开源` / `闭源` / `部分` | 权重可下载即算开源；`部分` 指权重可下载但许可证受限（如仅限研究）。另有 `待确认`，用于状态未公布的新模型 |
| 重要度 | ★★～★★★★★ | ★★★★★ 范式开创；★★★★ 代际标杆；★★★ 重要工程节点；★★ 有影响但可替代。主观，但标准固定 |
| 层数 | `12` / `12 / 24` / `24+24` | Transformer 块的数量。`/` 分隔同一代的两个尺寸（base / large），`+` 表示编码器 + 解码器 |
| 隐层 | `768` | 隐层维度 d_model，即 token 表示向量的宽度 |
| 头数 | `12` | 注意力查询头（Q head）数；用 GQA/MQA 的模型，KV 头数另在正文写明 |
| 参数 | `117M` / `175B` | 总参数量。`K`=千、`M`=百万、`B`=十亿、`T`=万亿；MoE 模型括号内为每 token 激活参数 |
| 激活 | `GELU` / `ReLU` / `SwiGLU` / `GeGLU` | FFN 的激活函数。`SwiGLU`≈`SiLU` 门控，`GeGLU`≈`GELU` 门控 |
| 位置编码 | `绝对·学习` / `相对` / `RoPE` / `ALiBi` / `iRoPE` | `绝对·学习` 是可学习的位置向量；`相对` 是相对位置（括号注明实现：偏置/解耦/T-XL 正弦） |
| 归一化 | `Post-LN` / `Pre-LN` / `Pre-RMSNorm` | 归一化算子 + 相对于子层的位置。`QK` 表示对 Q/K 额外做归一化 |
| 残差 | `串行` / `并行` | 串行 = 每个子层各包一层残差；并行 = Attention 与 FFN 共用同一个归一化输入、各自加回 |
| Softmax | `标准` / `标准+cap` / `稀疏` | 注意力里的 softmax 形式。`cap` 指 logit 上做软截断，`稀疏` 指先选 token 再归一化 |
| 编/解码 | `Enc` / `Dec` / `Enc-Dec` | 只用编码器、只用解码器、编码器-解码器 |

两个提醒：

1. **「归一化」和「残差」是两件事。** `Pre-LN` 说的是归一化放在子层之前，`串行` 说的是残差怎么接。GPT-1 是 `Post-LN + 串行`，GPT-2 是 `Pre-LN + 串行`，PaLM 是 `Pre-LN + 并行`——三种组合都存在，别混。
2. **闭源模型留空不是没查。** GPT-4 之后，头部厂商基本不再公开层数、激活、归一化位置。表里写 `—` 的格子，是「官方未披露」，不是「没有这个部件」。

> 先只看「激活 / 位置编码 / 归一化」三列，会看到三条清晰的断层线：
>
> - **2018–2019**：`GELU + 绝对位置 + Post-LN`，几乎是全行业默认。
> - **2020–2021**：`Pre-LN` 开始替代 `Post-LN`（GPT-2 先行，GPT-3 定型）。
> - **2022–2023**：`SwiGLU + RoPE + Pre-RMSNorm` 三件套出现，2023 年后成为开源默认。

## 三、分代速记

表格只有结论，这一节补上「为什么」和「怎么验证」。

### 2018–2020：编码器与解码器分立

**BERT（2018-10）** 把 Transformer 的编码器单独拎出来做掩码语言模型。`Post-LN`、`GELU`、学习式绝对位置，和 GPT-1 用的是同一套零件，区别只在注意力掩码的方向和训练目标。这两个模型的对照见 [[GPT与BERT]]。

**GPT-2（2019-02）** 的架构改动只有一句：把 LayerNorm 从残差之后挪到子层之前，并在最后再加一层 LN。就是这一挪，让 48 层能稳定训练——`Pre-LN` 的梯度不再经过一条 48 次连乘的路径。这是后面所有大模型的地基。

**T5（2019-10）** 做了三处减法：LayerNorm 去掉偏置只做缩放（即 RMSNorm）、相对位置偏置只加在注意力 logits 上、所有任务改写成 text-to-text。它是 `Pre-RMSNorm` 的第一个大规模用户，比 LLaMA 早三年半。

**XLNet（2019-06）** 与 **DeBERTa（2020-06）** 代表了另一条路：把位置信息做成相对量。XLNet 继承 Transformer-XL 的片段递归与相对编码，用排列语言模型绕开 `[MASK]`；DeBERTa 更进一步，把内容向量和位置向量解耦成两套注意力打分。这是 [[位置编码]] 里「相对 vs 绝对」那条线的源头。

**GPT-3（2020-05）** 架构上几乎没创新——`Pre-LN + GELU + 学习式位置`，96 层堆到 175B。它的意义在上下文学习：不改一个参数，只靠提示就能做新任务。从这一年起，「架构」不再是唯一变量，「规模 + 数据」成为同等重要的一维。

**Switch Transformer（2021-01）** 第一次把 MoE 推到万亿参数：每个 token 只走 1 个专家，参数量涨两个数量级而 FLOPs 几乎不变。它的路由设计（top-1、负载均衡损失）是后来所有 MoE 的祖先。

### 2021–2022：解码器统一与规模定律

**Gopher（2021-12）** 与 **Chinchilla（2022-03）** 是同一套架构的两个尺寸：`Pre-RMSNorm + Transformer-XL 那套相对位置编码`，参数从 280B 降到 70B。Chinchilla 的贡献不在结构，而在训练配比——**参数量与 token 数应当同比例增长**，20 token/参数才是 compute-optimal。这条结论直接改写了 2023 年之后所有人的数据预算。

**PaLM（2022-04）** 是第一个把 `SwiGLU + RoPE + 并行残差 + 无偏置` 打包上 540B 的模型。三处改动各自有明确收益：SwiGLU 比 GELU 的 FFN 质量更高；RoPE 让长序列外推更好；并行残差把 Attention 和 FFN 的矩阵乘融合，训练快 15%。这套组合后来被 LLaMA 原样继承。

**OPT-175B（2022-05）** 是 GPT-3 的开源复刻，`ReLU + 学习式位置 + Pre-LN`，连 175B 的参数形状都对齐。它的价值是让学术界第一次能拿到百亿级以上的完整权重，代价是训练过程极不稳定（日志里大量 loss 尖峰）。

**BLOOM（2022-11）** 换掉了位置编码：用 `ALiBi` 直接在注意力分数上按距离扣分，彻底不学位置向量。它还在词嵌入后额外加了一层 LayerNorm——这是为了 bf16 数值稳定做的工程补丁，不是架构必需。

### 2023：开源追平

**LLaMA（2023-02）** 是分水岭。`SwiGLU + RoPE + Pre-RMSNorm + 去掉所有偏置`，13B 在多数基准上超过 175B 的 GPT-3。它证明了一件事：**架构选对了，参数量的需求可以降一个数量级。** 2023 年之后几乎所有开源模型都是它的变体。

**Llama 2（2023-07）** 只加了两样：34B/70B 上用 GQA（8 个 KV 头共享），上下文拉到 4096。**Mistral 7B（2023-09）** 在此之上加了滑动窗口注意力（SWA）：每层只看最近 4096 个 token，推理时 KV cache 不随上下文长度线性涨。**Mixtral 8x7B（2023-12）** 把 FFN 换成 8 个专家、每 token 走 2 个，46.7B 总参数只激活 12.9B——开源 MoE 的起点。

**Falcon（2023-05）** 走的是另一条分支：`ALiBi + 并行残差 + 多查询注意力`，40B 在当年一度是开源榜首。它的并行残差写法（Attention 和 FFN 同时读同一个 LN 输出）后来被 PaLM 之外的模型较少采用，但在推理吞吐上确实更省。

### 2024：MoE、长上下文、多模态

**DeepSeek-V2（2024-05）** 提出 MLA（多头潜在注意力）：把 KV 压到低维潜向量再缓存，KV cache 减少 90% 以上。配合 DeepSeekMoE 的「细粒度专家 + 共享专家」，236B 总参数只激活 21B。这是 2024 年最有影响力的架构创新，后来被 Kimi K2 等直接采用。

**Llama 3（2024-04）** 把词表从 32K 扩到 128K，RoPE 基频从 10K 提到 500K，上下文 8K。405B 版本保持稠密——Meta 在 MoE 上晚了一步，这也成了 Llama 4 转向 MoE 的直接原因。

**Gemma 2（2024-06）** 做了两个不常见的选择：GeGLU 代替 SwiGLU；注意力层交替使用局部窗口（4K）和全局窗口（8K）。另外在注意力 logits 上加了 tanh 软截断（`cap=50`），输出 logits 上再加一层（`cap=30`）——这是 [[Softmax与采样]] 里温度之外的另一条稳定化路径。

**Qwen2（2024-06）** 在 LLaMA 骨架上加回了 QKV 偏置，小模型上共享输入输出词嵌入。**Phi-3（2024-04）** 则证明 3.8B 在高质量数据上可以逼近 10 倍参数的老模型——架构没变，变的是数据配比。

### 2025：推理模型与混合架构

**DeepSeek-V3（2024-12）/ R1（2025-01）** 把两件事同时做成：架构上 `MLA + 无辅助损失的负载均衡 + FP8 训练`，训练上 `R1` 用纯 RL（GRPO）激发出长思维链，且权重开源。R1 的意义不在结构——它和 V3 是同一套骨架——而在于证明了**推理能力可以不靠人工标注的思维链，只靠可验证的奖励信号长出来**。

**Qwen3（2025-04）** 把「思考 / 不思考」合并进一个模型，靠一个开关切换；架构上在 Q/K 上加了 QK-Norm，缓解长上下文下注意力 logits 的数值爆炸。

**Llama 4（2025-04）** 全面转 MoE，并引入 iRoPE：大部分层用 RoPE，每第 4 层改成无位置编码（NoPE），靠注意力自身推断相对位置，从而在推理时外推到训练长度之外。

**Kimi K2（2025-07）** 把开源 MoE 推到 1T 参数（32B 激活），384 个专家选 8 个，注意力沿用 MLA。它的工程贡献是 MuonClip 优化器——在 Muon 上加了 QK-Clip，解决万亿参数训练的发散问题。

**DeepSeek-V3.2（2025-12）** 把注意力改成 DSA（稀疏注意力）：先用一个轻量 indexer 给 token 打分，只对 top-k 做完整注意力，长上下文成本大幅下降。这一步是 V3.2-Exp（2025-09）先落地的，V3.2 只是把它转正并补齐了工具调用。

### 2025–2026：版本迭代取代了架构换代

这一段的表最密，但真正换架构的只有 DeepSeek 一家，其余全是同一套骨架的版本推进。

**OpenAI 从 GPT-5 起改成「一代 + 多档」**：`gpt-5`（2025-08）同时发 `mini` / `nano`，之后 5.1 → 5.2 → 5.3（codex / chat 分叉）→ 5.4（pro / mini / nano）→ 5.5 → 5.6（sol / terra / luna 三档推理档位）→ GPT-6（2026-09）→ 6.1。**版本号之外的信号是能力档位**：`-pro` 留给最重的推理，`-codex` 走代码 agent，`sol / terra / luna` 是同一代里按成本切的三个推理深度。组件一个都没有公开。

**Anthropic 的节奏是「小步快跑 + 家族扩张」**：`Opus 4.5`（2025-11）之后 4.6 / 4.7 / 4.8 以两个月一档推进，2026-06 起开出 `Fable`（通用可用）与 `Mythos`（更强但受限）两条线，随后 `Opus 5`（2026-07）→ `Fable 5.1`（2026-09）→ `Opus 5.5 / Sonnet 5.5 / Haiku 5.5`（2026-09 至 10）补齐整个家族。所有版本都不披露层数与组件。

**Google 从 Gemini 3 起用小版本号切 Flash 档**：`3 Pro`（2025-11）→ `3 Flash`（2025-12）→ `3.1 Pro / Flash-Lite`（2026-02 至 03）→ `3.5 / 3.6 / 3.7 / 3.8 Flash`（2026-05 至 09）→ `Gemini 4 Argon`（2026-10）。Pro 与大版本同步，Flash 走月度小版本，这是为了跟上推理成本下降的速度。

**DeepSeek 是唯一把版本号和结构变化绑在一起的**：`V3-0324`（2025-03）只是重训，`V3.1`（2025-08）是混合推理，`V3.1-Terminus`（2025-09）修语言一致性，`V3.2-Exp`（2025-09）换成 DSA 稀疏注意力，`V3.2`（2025-12）转正。

`V4`（2026-04）换了一代新架构，而且权重照旧开源，`config.json` 能直接读出全部数字：Pro 是 61 层 / 7168 维 / 128 头，384 个路由专家 + 1 个共享专家、每 token 选 6 个；Flash 是 43 层 / 4096 维 / 64 头，256 + 1 专家、同样选 6 个。两者都把 KV 头压到 **1 个**、head_dim 抬到 **512**，上下文默认 1M（RoPE + YaRN ×16），注意力是「token 级压缩 + DSA」。

`V4.1-Flash`（2026-09）又改了一次结构：552B 的 MoE，但换成**非对称因果编码器-解码器**——输入侧只激活 8B、输出侧 16B，KV cache 只要上一代的 1/4。这是 2026 年唯一一次真正的架构改动，不是重训。

一句话总结这一段的规律：**2023 年之前看架构，2025 年之后看版本节奏**。同一代里每两三个月推一版，靠后训练和推理栈吃收益，架构只是底座。

## 四、六个部件各自的路线

把表竖着读，六条线各自收敛得很快。

### 激活函数：ReLU → GELU → 门控

`ReLU`（T5、OPT、Switch）→ `GELU`（GPT 系、BERT 系）→ `SwiGLU / GeGLU`（PaLM 之后）。

门控线性单元的本质是把 FFN 从「一个升维矩阵 + 激活 + 一个降维矩阵」改成「两路升维，一路过激活，两路逐元素相乘」。同等参数量下质量更好，代价是 FFN 多了一个矩阵——所以 LLaMA 把 `d_ff` 从 `4d` 降到 `8/3·d` 来抵消。细节见 [[前馈网络]]。

### 位置编码：绝对 → 相对 → 旋转

学习式绝对位置（GPT-1/2/3、BERT）→ 相对位置（T5 的可学习偏置、Gopher 的 Transformer-XL 正弦、DeBERTa 的解耦矩阵）→ RoPE（PaLM、LLaMA 系）→ ALiBi（BLOOM、Falcon）→ iRoPE / NoPE（Llama 4）。

2022 年之后 RoPE 基本统一了开源阵营，原因是它同时具备两个性质：相对位置的内积形式，以及可以通过改基频（`rope_theta`）做长度外推。ALiBi 更简单但外推能力在长上下文任务上不如 RoPE + 插值。详见 [[位置编码]]。

### 归一化：Post-LN → Pre-LN → RMSNorm

`Post-LN`（原始 Transformer、BERT、GPT-1）→ `Pre-LN`（GPT-2 起）→ `RMSNorm`（T5 起，LLaMA 定型）→ `QK-Norm`（Qwen3 起，只归一化 Q/K）。

这条线的驱动力只有一个：**深层网络的数值稳定性**。Post-LN 在 24 层以上需要 warmup 才能收敛；Pre-LN 把这个约束去掉了，但表达力略降；RMSNorm 去掉均值中心化，省一次 reduce，速度更快。见 [[Transformer块]]。

### 残差：串行 → 并行

`串行`（默认）→ `并行`（PaLM、Falcon、GPT-J）。

并行残差让 Attention 和 FFN 读同一个归一化输出、各自加回主干。收益是训练时两个矩阵乘可以拼成一个大矩阵乘，吞吐提升约 15%；代价是表达力略降。2023 年后主流模型基本回到串行——因为 MoE 和长上下文带来的收益远大于这 15%。

### Softmax：标准 → 稀疏 / 截断

注意力里的 softmax 极少被替换，变的是**在什么范围内做 softmax**：

- **标准**：对全部可见 token 归一化。
- **稀疏**（DeepSeek-V3.2 起、V4 继续用的 DSA）：先用轻量 indexer 给 token 打分，只对 top-k 做完整注意力
- **滑窗 + 压缩**（V4.1）：`sliding_window=128`，同时在 KV 上做 token 级压缩（`compress_ratios`），把远处上下文压成更少的槽位
- **软截断**（Gemma 2）：`logits ← cap · tanh(logits / cap)`，防止极端值把 softmax 推到 one-hot。

真正的「无 softmax」线性注意力（MiniMax-01 的 lightning attention 等）目前只在少数模型上做混合使用，还没成为主线。采样端的故事另见 [[Softmax与采样]]。

### 编解码：三分之后归一

2018–2019 是三分天下：`Enc`（BERT）、`Dec`（GPT）、`Enc-Dec`（T5）。2020 年之后解码器一路通吃，原因是**同一个模型能同时做理解和生成**，且 scaling 行为更可预测。到 2024 年，除 T5 系和少量检索/翻译专用模型，主流全部是 `Dec`。

唯一的回摆出现在 2026 年：DeepSeek-V4.1 把输入侧和输出侧拆成两个不同大小的专家子网（编码 8B / 解码 16B），用非对称的编码-解码换推理成本。MoE 之后，编解码又在成本这条轴上复活了——但动机已经和 2019 年的 T5 完全不同：T5 是为了统一任务形式，V4.1 是为了把「读长上下文」和「写长答案」的算力分开计费。

## 五、如果只记十个节点

1. **GPT-2 把 LN 挪到前面**（2019）——深层训练从此不再依赖精细的 warmup。
2. **T5 用 RMSNorm + 相对偏置**（2019）——预演了三年后的主流配置。
3. **GPT-3 证明上下文学习**（2020）——架构之外的第二个缩放轴。
4. **Switch 把 MoE 做到万亿**（2021）——稀疏激活成为参数量的新杠杆。
5. **Chinchilla 修正数据配比**（2022）——20 token/参数。
6. **PaLM 打包 SwiGLU + RoPE + 并行**（2022）——现代解码器的配方。
7. **LLaMA 证明小模型可以打赢大模型**（2023）——开源生态的起点。
8. **MLA 把 KV cache 压下去**（2024）——长上下文的经济学。
9. **R1 证明纯 RL 能长出推理**（2025）——后训练范式的转向。
10. **DSA / iRoPE 把注意力本身变稀疏**（2025）——稀疏从「专家」扩展到「token」。

再往后就没有「第 11 个节点」了：2025 年下半年起，厂商的收益主要来自后训练与推理栈，架构在一年内反复复用，同一个底座能推十几个版本。所以这张表后半段的看点是**版本节奏**，不是部件。

## 六、维护这张表

这张表按季度补，加一行的流程是固定的。

**1. 按版本收，不按家族收。** 同一条线每发一版就加一行，`版本` 列写代号（`mini` / `Pro` / `Flash` / `0324` / `GA`）。判断标准只有一条：官方是否对外发布了这个可调用的模型。图像、视频、语音、TTS、嵌入、机器人类模型不收。

**2. 时间以官方发布为准。** 论文 arXiv 日期、官方 blog 日期、API 上线日期三者常常不同。本表统一取**首次公开发布**日期，精确到月。

**3. 组件以论文表格为准，不以博客为准。** 论文里的 "Table 3: key hyperparameters" 通常直接给出 `Activation Function`、`Positional Embeddings`、`Vocabulary Size`、`Layers`、`Attention Heads`。Llama 3 那张表就是这么写的：

> Activation Function `SwiGLU`；Positional Embeddings `RoPE (θ=500,000)`；Vocabulary Size `128,000`

**4. 开源模型可以直接查 config。** Hugging Face 的 `config.json` 里，六个组件里有四个是明文字段：

| 组件 | config 字段 | 例子 |
| --- | --- | --- |
| 激活 | `hidden_act` | `"silu"` 即 SwiGLU |
| 位置编码 | `position_embedding_type` / `rope_theta` | `"rope"`, `500000.0` |
| 归一化 | `rms_norm_eps`（有则 RMSNorm）/ `layer_norm_eps` | `1e-6` |
| 层数/宽度 | `num_hidden_layers` / `hidden_size` / `num_attention_heads` | `80 / 8192 / 64` |

残差和 softmax 不在 config 里，要看建模代码（`modeling_*.py`）或论文。这也是为什么表里这两列最容易出错。

Hugging Face 打不开时，ModelScope 的接口能直接取到同一份文件：

```
https://modelscope.cn/api/v1/models/{org}/{name}/repo?Revision=master&FilePath=config.json
```

DeepSeek 全系（V2 到 V4.1）的组件列都是这么核对出来的。

- 中国阵营：GLM-4.5 / 4.6（智谱）、MiniMax-M2、Yi-Large（零一万物）、ERNIE 4.5（百度）

- Google 的 Omni / TTS / Live / Transcribe 分支，以及各家图像、视频、语音模型——按收录规则不进这张表

这些没进表，是因为还没核到官方日期或组件；宁缺勿错。

**6. 闭源模型只写能证实的。** 官方报告里没有的，一律 `—`。传闻（比如 GPT-4 是 8×220B MoE）写进正文并标明「未证实」，不要进表格。

**7. 开源模型不许留空。** 只要权重能下载，层数 / 隐层 / 头数 / 激活 / 归一化就必须填满——`config.json` 里全都有。`未公开` 只允许出现在闭源模型上；开源模型写 `未公开` 不是「查不到」，而是没查。
