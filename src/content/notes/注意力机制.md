> [!info] 在主线的哪一步
> 这是主线「第 3 步：让词与词直接交换信息」的展开。主线只需要知道：注意力让每个位置直接读取序列里的其他位置，权重由内容决定。这一篇把 Q、K、V 拆开，讲清楚它为什么这样算、代价是什么。

## 一句话版本

注意力是一次**按内容检索**：每个位置发出一个 query，和所有位置的 key 比较，得到一组权重，再对所有位置的 value 加权求和。输出是「这个位置此刻需要的上下文」，而不是一个固定的句子摘要。

## 为什么「压成一个向量」不够

在注意力之前，把变长句子变成定长表示的常见办法是 RNN 的最后一个隐藏状态，或者池化。它们共享一个瓶颈：

- 句子有 5 个词还是 500 个词，最后都要挤进同一个 $d$ 维向量。
- 解码时，生成第 1 个词和第 50 个词，用的是同一份摘要。但这两个时刻真正需要的信息往往不同。
- 长距离依赖要经过很多步传递，梯度容易衰减。

注意力换了一个思路：**不压缩，保留每个位置的表示；需要谁的信息，就当场去取。** 生成每个词时，模型都可以重新分配一次注意力权重。

## Q、K、V 分别是什么

同一个输入矩阵 $X \in \mathbb{R}^{n \times d}$，用三组可学习权重投影出三个角色：

$$
Q = XW_Q,\qquad K = XW_K,\qquad V = XW_V
$$

可以把它想成查字典：

| 角色 | 类比 | 作用 |
| --- | --- | --- |
| Query（Q） | 我要查什么 | 当前这个位置发出的「需求」 |
| Key（K） | 词条标题 | 每个位置能提供什么的「索引」 |
| Value（V） | 词条内容 | 真正被加权取走的信息 |

$QK^{\top}$ 是一个 $n \times n$ 的矩阵，第 $i$ 行第 $j$ 列表示「第 $i$ 个位置对第 $j$ 个位置的兴趣分数」。Softmax 按行归一化，得到每个位置对其他所有位置的权重，最后用这些权重对 $V$ 加权求和。

## 完整公式

$$
\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V
$$

三个细节值得单独说：

### 1. 为什么要除以 $\sqrt{d_k}$

假设 $q$ 和 $k$ 的每一维都是均值 0、方差 1 的独立随机变量，那么它们的点积：

$$
q \cdot k = \sum_{i=1}^{d_k} q_i k_i
$$

的方差是 $d_k$，标准差是 $\sqrt{d_k}$。维度越大，分数越容易变得很大。Softmax 对大的输入非常敏感：一旦某一项远大于其他项，输出就接近 one-hot，梯度几乎消失，训练会停滞。

除以 $\sqrt{d_k}$ 把点积的尺度拉回 1 附近，让 softmax 工作在梯度比较健康的区间。这是数值稳定性的需要，不是可有可无的装饰。

### 2. Softmax 是按行做的

对第 $i$ 行做 softmax：

$$
\alpha_{ij} = \frac{\exp(s_{ij})}{\sum_{j'=1}^{n}\exp(s_{ij'})}
$$

所以每个位置分到的权重加起来是 1。它不是「全局重要度」，而是「第 $i$ 个位置把 100% 的注意力如何分给所有位置」。

### 3. 输出长度不变

输入 $n$ 个向量，输出还是 $n$ 个向量。注意力只改变每个位置的内容，不改变序列长度。这一点让它可以被反复堆叠，也是 Transformer 能做成「块」的前提。

## 多头：让不同的头学不同的关系

一个头只有一组 $W_Q, W_K, W_V$，只能表达一种「怎么比较」。语言里的关系远不止一种：主谓、指代、修饰、位置相邻……多头让模型并行地学多组关系：

$$
\operatorname{head}_i = \operatorname{Attention}\!\left(XW_i^Q, XW_i^K, XW_i^V\right)
$$

$$
\operatorname{MHA}(X) = \operatorname{Concat}(\operatorname{head}_1,\dots,\operatorname{head}_h)\,W_O
$$

每个头的维度通常是 $d_k = d/h$，所以总计算量和单头差不多，只是把「一个 $d$ 维的注意力」拆成 $h$ 个「$d/h$ 维的注意力」。最后拼接起来，再过 $W_O$ 融合。

> [!note] 多头不是简单的集成
> 不同的头确实会分化出不同的行为（有的看相邻位置，有的看句法依存，有的几乎只关注自己），但这不是硬性保证。训练后有些头可以被剪掉而性能几乎不掉，说明存在冗余。头数和头维度是超参数，不是越多越好。

## 因果掩码：生成模型不能偷看未来

语言模型训练时是「给定前文，预测下一个词」。如果第 $i$ 个位置能注意到第 $i+1$ 个位置，那它直接抄答案就行了，训练会失效。

做法是在 softmax 之前，把「未来」位置的分数设成 $-\infty$：

$$
A = \operatorname{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d_k}} + M\right),
\qquad
M_{ij} =
\begin{cases}
0, & j \le i \\
-\infty, & j > i
\end{cases}
$$

以 3 个 token 为例，可见性是这样的：

BERT 这类 encoder 不用因果掩码，所有位置互相可见（双向）；GPT 这类 decoder 用因果掩码（单向）。这是两类模型最本质的区别之一，详见 [[GPT 与 BERT]]。

## 代价：O(n²) 从哪里来

长度为 $n$ 的序列，注意力要算一个 $n \times n$ 的分数矩阵，每个元素是一次 $d$ 维点积：

- 时间：$O(n^2 d)$
- 显存：朴素实现要存 $n \times n$ 的权重，$O(n^2)$
- 生成时：每多一个 token，都要和之前所有 token 算一次

这就是「上下文越长越贵」的根源。围绕它有大量工程优化：

| 优化 | 思路 | 代价 |
| --- | --- | --- |
| KV Cache | 生成时缓存历史 token 的 K/V，不重复计算 | 显存随上下文线性增长 |
| FlashAttention | 分块计算，不把完整 $n \times n$ 矩阵写回显存 | 实现复杂，但数学上等价 |
| GQA / MQA | 多个 query 头共享少量 KV 头 | 牺牲一点表达力，换显存和带宽 |
| 滑窗 / 稀疏注意力 | 每个 token 只看局部窗口或选中的位置 | 长距离依赖要绕路 |
| 线性注意力 | 用核函数近似 softmax，做到 $O(n)$ | 效果和生态仍在演进 |

> [!tip] 一个判断
> 看到「支持 100 万 token 上下文」时，先问三个问题：训练时真的见过这么长吗？注意力是 full 还是稀疏/滑窗？KV Cache 占多少显存？「能放进去」和「能用好」是两件事。

## 代码：最小实现

```python
import math
import torch
import torch.nn.functional as F

def attention(q, k, v, causal: bool = False):
    # q, k, v: [batch, heads, seq, d_k]
    d_k = q.size(-1)
    scores = q @ k.transpose(-2, -1) / math.sqrt(d_k)

    if causal:
        n = q.size(-2)
        mask = torch.triu(torch.ones(n, n, dtype=torch.bool, device=q.device), diagonal=1)
        scores = scores.masked_fill(mask, torch.finfo(scores.dtype).min)

    weights = scores.softmax(dim=-1)
    return weights @ v, weights
```

PyTorch 2.x 也提供了融合实现：

```python
out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
```

它会在底层选择 FlashAttention 或内存高效的 kernel，数值结果和上面的手写版一致（边界情况略有差异）。

## 三个常见误解

1. **「注意力权重就是解释」**。权重高只说明这个位置在这次前向里被加权得多，不代表模型的决策原因。注意力头之间存在冗余，后续层还会重新混合，把某一层的权重直接当成「模型在看哪里」并不可靠。
2. **「注意力负责记住上下文」**。注意力负责**搬运**信息，真正把信息写进参数、形成长期知识的是 FNN 和训练过程。上下文窗口里的内容也不是「记住」，只是这次前向可见。
3. **「多头一定比单头强」**。头数增加会提升表达力，但也带来冗余和计算开销。很多模型会剪掉部分头，性能几乎不变。

## 回到主线

注意力解决了「词与词怎么交流」，但顺手制造了一个新问题：它对输入顺序不敏感。把「今天 天气 真」打乱，输出只是跟着打乱，模型看不出谁在前谁在后。
