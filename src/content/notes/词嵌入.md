## 一句话版本

分词器把句子切成 token，每个 token 对应一个整数 id；Embedding 是一张可学习的查找表，用 id 取出一个 $d$ 维向量。查表在数学上等价于 one-hot 向量乘矩阵，但在实现上只是取一行。

## 从文本到 id：分词器先做一次切分

神经网络不认字，只认整数。分词器（tokenizer）负责把字符串切成 token，并给每个 token 一个 id：

```text
"今天天气真好"  →  ["今天", "天气", "真", "好"]  →  [872, 3319, 4021, 918]
```

切分粒度直接决定了词表大小和序列长度：

| 粒度 | 例子 | 优点 | 代价 |
| --- | --- | --- | --- |
| 按词 | `today` / `天气` | 一个 token 信息量大，序列短 | 词表爆炸，没见过的词变成 OOV |
| 按子词 | `un` + `believ` + `able` | 能拼出没见过的词，词表可控 | 一个词被拆成多个 token，序列变长 |
| 按字符 / 字节 | `天` / `气` | 词表最小，任何输入都能表示 | 序列最长，模型要自己学组合 |

现代模型基本都用子词方案。BPE（Byte Pair Encoding）的思路很朴素：从字符或字节开始，统计语料里最常相邻出现的一对符号，把它们合并成新符号，重复到词表达到目标大小。`low`、`lower`、`lowest` 这类词会共享 `low` 这个子词，模型因此能复用语素。

中文常用字词混合的子词表；有些模型直接在字节层面做 BPE，好处是任何 Unicode 文本都不会 OOV，代价是中文一个汉字可能要占 2–3 个 token。

> [!warning] 一个容易忽略的坑
> 分词器是**训练时固定**的。换分词器等于换词表，Embedding 矩阵的形状和每一行的含义都会变，旧权重不能直接复用。微调一个已经预训练好的模型时，分词器必须和 checkpoint 配套。

## one-hot 的问题

最直接的「把词变成数字」是 one-hot：词表有 $V$ 个词，第 $i$ 个词就是一个长度为 $V$ 的向量，只有第 $i$ 位是 1。

```text
"猫"   → [1, 0, 0, 0, …]
"狗"   → [0, 1, 0, 0, …]
"石头" → [0, 0, 1, 0, …]
```

它有两个致命问题：

1. **维度等于词表大小**。GPT-3 的词表是 50257，一个 token 就是五万维的稀疏向量，计算和存储都浪费。
2. **任意两个词的距离都一样**。one-hot 向量的内积为 0、欧氏距离都相等，「猫」和「狗」的相似度并不比「猫」和「石头」高。语义信息完全没有进入表示。

## Embedding：把 one-hot 换成一个可学习的矩阵

我们想要一个稠密、低维、能学的表示。做法是引入矩阵 $E \in \mathbb{R}^{V \times d}$，第 $i$ 行就是第 $i$ 个 token 的向量：

$$
x_t = E[\operatorname{id}(w_t)] \in \mathbb{R}^{d}
$$

如果把 one-hot 向量记作 $e_i$，那么 $x_t = E^{\top} e_i$——**查表就是一次稀疏矩阵乘法**。实现时当然不会真的构造 one-hot，而是直接按行索引：

```python
import torch
import torch.nn as nn

vocab_size, d_model = 32000, 4096
embedding = nn.Embedding(vocab_size, d_model)

ids = torch.tensor([[872, 3319, 4021]])  # [batch=1, seq=3]
x = embedding(ids)                       # [1, 3, 4096]
```

`nn.Embedding` 内部就是一张 `[vocab_size, d_model]` 的表，前向时按 id 取行，反向时只更新被取到的那几行。所以 Embedding 的梯度是**稀疏**的：一个 batch 里没出现的 token，这一步不会被更新。

## 向量里到底学到了什么

Embedding 的每一行一开始是随机初始化的。训练之后，经常出现在相似上下文里的词，向量会靠近——因为模型要预测下一个词，必须把「今天天气真___」里的「好」和「不错」「棒」放到相似的位置上。

这带来几个常被提到的现象：

- **相似度**：$\cos(x_{\text{猫}}, x_{\text{狗}}) > \cos(x_{\text{猫}}, x_{\text{石头}})$。
- **线性关系**：在足够大、足够干净的词向量里，可能出现 $x_{\text{国王}} - x_{\text{男人}} + x_{\text{女人}} \approx x_{\text{女王}}$ 这样的方向。它是训练数据的副产品，不是每条都成立。
- **聚类**：颜色、国家、动词时态等语义维度会形成局部结构。

> [!note] 这是「静态」词向量
> 输入 Embedding 对同一个 token 永远给出同一行向量，和上下文无关。让「苹果」在「吃苹果」和「苹果发布手机」里有不同表示，是后面 Attention 层做的事。不要把输入 Embedding 和上下文表示混为一谈。

## 维度、参数量和权重共享

Embedding 的参数量是 $V \times d$。它经常被低估：

| 模型 | 词表 $V$ | 维度 $d$ | Embedding 参数量 |
| --- | --- | --- | --- |
| GPT-2 small | 50257 | 768 | ≈ 38.6M |
| BERT-base | 30522 | 768 | ≈ 23.4M |
| GPT-3 | 50257 | 12288 | ≈ 617M |

对 GPT-3 来说，Embedding 只占总参数 175B 的千分之三左右，看起来不多；但对小模型，它可能占到三分之一。

**权重共享（weight tying）** 是一个常见优化：让输入 Embedding 和输出层（LM Head）共用同一个矩阵。输出 logits 是 $h E^{\top}$，而输入是 $E x$，两者共用 $E$ 在直觉上说得通——「词向量」和「预测词的模板」本来就是同一套语义空间。GPT-2、T5 等模型用了这种结构；也有些模型选择不共享，因为输入和输出需要的表示并不完全一样。

## 分词粒度为什么会反过来影响模型

分词不是预处理里无关紧要的一步，它会改变模型看到的序列：

- **序列长度**：同样一句话，按字切可能比按词切长一倍，Attention 的 $O(n^2)$ 成本直接翻四倍。
- **词表大小**：词表越大，Embedding 和 LM Head 越大，低频词的训练样本越少。
- **跨语言**：中文、日文、代码、数学公式混在一起时，分词器对哪些字符合并、哪些拆开，会直接影响模型在这些领域的表现。
- **数字**：很多分词器把 `12345` 拆成 `123` + `45`，模型因此很难学会逐位运算。这是「LLM 算术不好」的原因之一，不是全部。
